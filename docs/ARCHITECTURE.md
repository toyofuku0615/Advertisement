# 設計書

## 方針と構成

収集と閲覧を分離した静的アプリ。フロントエンドは React / TypeScript / Vite、Tailwind 4、Radix を使う shadcn 型のローカル UI 部品、Lucide、Recharts、MapLibre GL JS。収集は Python 3.12 の標準ライブラリのみ。API キー・プロキシの認証情報は収集プロセスの環境に限定し、公開 JSON に含めない。

```text
公式 RSS / 公開 API / 公式固定履歴
             │ Python: 取得・形式検証・重複排除・保持期限
             ▼
public/data/dataset.json ── 静的配信 ── React画面
       │                                   │
       ├─ archive-provenance.json           ├─ MapLibre + 同梱GeoJSON
       └─ archive-environment-selected.csv  ├─ Recharts
                                           └─ IndexedDB（個人研究・CSV取込）
```

第三者の有料 DB や API サーバーを必須にしないため、手元の静的サーバーや条件を満たす無料ホスティングで動く。地図は Natural Earth の GeoJSON を同梱し、外部タイルサーバーの課金や利用枠に依存しない。標準 JSON のスキーマを収集器と TypeScript で共有し、将来の DB 移行はデータ取得層で吸収する。

## データモデルと根拠

| 概念 | 現在の実装と関係 |
| --- | --- |
| Topic | 現象・話題。収集器は NFKC と大小文字の一致以外で意味統合しない。表示名と取得原文は別 |
| TopicAlias | `Topic.aliases`。言語・表記と ID。ユーザー修正はローカルの `TopicMapping` に保存し、原典観測を改変しない |
| Source | 取得元、種別、URL、規約URL、指標定義、ライセンス、設定の有無 |
| Observation | 元データID、原典URL、投稿/観測/取得時刻、地域と地域の意味、指標名・値・単位・正規化、母集団、取得方法、権利、鮮度 |
| GeoObservation | 地域・観測日・レイヤー・値・単位・正規化・母集団・URL。検索市場と報道機関所在国を分ける |
| Evidence | `repository.ts` の独立した読み取りモデル。永続原本は Observation / GeoObservation のURL・ID・取得時刻 |
| AudienceEvidence | 調査母集団・標本数・時期・属性・地域・設問・方法・比較キー・値・URL。利用者の CSV はブラウザ内保存 |
| ContentItem | `repository.ts` の独立した読み取りモデル。永続原本は Observation のタイトル、元ID・URL・公開日時。投稿全文・動画ファイルは保管しない |
| CreativeAnalysis | 原典URL、ブランド、3秒、フック、コピー、構図、物語、出演者、感情、CTA、確認指標、手動メモ |
| InsightHypothesis | 対象トピック、編集した仮説、対応する観測ID、更新日時 |
| SavedResearch | 話題、検索条件、発見・メモ、保存日時・前回閲覧時刻 |
| Brief | ブランド・商品情報・ターゲット・競合・課題、参照トピック、編集内容、更新日時 |
| CollectionRun | 情報源別・地域別の開始/終了日時、成功/失敗/無効化、件数、安全なエラー説明 |

`reliability: observed` は、取得した観測であることを表す。意味の真実性・統計的代表性・外部の原典内容を検証済みと認定するフラグではない。ユーザーの手動メモや仮説は実測に変換しない。

## 収集処理

1. 既存 JSON が読めることとスキーマを確認。壊れていれば上書きせず終了
2. 公式手段に限定して取得。TLS・CA・プロキシ設定を継承。応答上限8 MiB、タイムアウト、有限回の再試行
3. 429 / 一部5xx / 一時的通信失敗にのみ待機付き再試行。宛先制限403を繰り返し回避しない
4. 日付・URL・必須フィールド・指標値を検証し、API形式変更を失敗として記録
5. 情報源の元IDと観測日時から安定したIDを作成。地域集計でも原典URLと定義を維持
6. 期限内の既存観測と新規観測をIDで統合。関係を再構築し、JSONを一時ファイルから原子的に保存

Google RSS は話題の公開時刻であり、急上昇開始時刻を保証しない。GDELT の `seendate` は GDELT の初観測時刻で、記事公開日時ではない。Bluesky は投稿日時と取得時点の反応数を別に保持。YouTube は `mostPopular` の選択地域と動画の視聴者国を同一視しない。

## 保持・再取得・削除

- Google/GDELT の現行データは観測日時から30日。YouTube のキャッシュは取得日時から30日、Bluesky は取得日時から24時間。同じ Bluesky の検索/アカウント母集団は正常再取得時に新しい標本で置換し、標本に返らないことだけで原投稿削除を推定しない。期限内の旧データは部分失敗時に stale として残す
- 固定コミットの Google 公式年次アーカイブは実履歴であると明示し、現行データとは別モードで保持。0の意味が不明な原データは0の国として地図を塗らない
- 実行履歴は最大160件。保持期限の適用は収集を実行したときで、静的ファイル自体が時間経過だけで削除されるわけではない
- 個人の CSV・メモ・広告分類は IndexedDB。自動失効・クラウド同期をせず、利用者が削除・バックアップする
- SNS の削除要請、取得元の利用条件変更には運用者の対応が必要。一般公開時には連絡先と削除フローを用意し、元データ削除への自動追従・検知は追加実装する

## 地理・時系列・指標

MapLibre の塗り分けはレイヤーの定義ごとに行い、検索関心と報道量を混ぜない。未観測地域を0で埋めない。アニメーションは実際に存在する観測日時だけを使い、補間しない。年次資料の代表日を日次計測と誤認しない。CSVの正規化・母集団が異なる系列は順位や伸び率で混ぜない。

Google 公式履歴の `index_trends` は正規化範囲が不明なため国間値比較を制限し、国ごとの年次推移の探索に使う。時系列上の先行・遅行は世界への伝播や因果を示さない。指標の式・必要な観測数・欠損条件は [METRICS.md](METRICS.md) に記載。

## UI と個人データ

画面はハッシュで切り替えるため、静的ホスティングに特別なルーティング設定は不要。RADAR の検索条件は sessionStorage、個人研究は IndexedDB。原典は新しいタブで開き、作業を維持する。ダークモード・レスポンシブ表示、読込・空・失敗状態を持つ。ブラウザの保存に失敗した場合は通知し、成功したと見せない。

URL は http(s) と資格情報を含まない形式に制限し、React のエスケープを通して表示する。CSV出力では表計算ソフトへの式注入に配慮する。ブラウザの研究内容は公開 JSON や GitHub に自動送信しない。外部リンクを開いた際は遷移先のプライバシー条件が適用される。

## 分析・将来の差し替え

現在は有料 LLM を使わず、根拠のある事実をテンプレートで整理し、仮説・反対解釈・次の検証を別欄で示す。主張を観測 ID に結び付け、根拠のない人口統計・数値・確率を生成しない。簡易キーワード検査は完全なブランドセーフティ審査を代替しない。

将来は `Dataset` 読込層を SQLite / DB / API adapter に差し替え、Evidence と ContentItem を独立した永続モデルに分離できる。ローカルOllamaでの任意の文脈解説生成に対応。ブラウザ内の対話型LLMは未実装。追加時にも出典 ID を入力・出力し、モデルの生成文を実測値として保存しない。Notion、認証、同期は別の adapter として追加し、現行の無料・静的ワークフローを残す。

## 静的リポジトリ境界と読み取りモデル

`src/lib/repository.ts` の `parseDataset` は、配信 JSON のバージョン、参照 ID、原典 URL、日時、指標値、地域の意味を画面に渡す前に検証します。スキーマ変更を空データとして扱わず、読み込みエラーにします。`Evidence` と `ContentItem` は、元の `Observation` / `GeoObservation` から ID を追跡できる独立した読み取りモデルです。永続 JSON の二重化はせず、将来の DB adapter でも同じ根拠を参照できます。原投稿へのリンクと関連記事へのリンクを、投稿者リンクとして混同しません。

## AI文脈解説

公開JSONとは別に `explanations.json` を静的配信し、`src/lib/explanations.ts` で引用ID・URL・日時・区分を検証します。入力を正規化したSHA-256はPython生成側とブラウザ側で共通です。取得日時だけの更新では本文を再生成せず、見出し・関連URL等の変更を古い解説として区別します。要約と利用場面の仮説を分け、空の根拠や不明な出典をAI説明として採用しません。

初期解説はCodexによる実際の生成結果。任意のローカルOllama adapterは収集機のloopbackだけへ接続し、クラウドモデルを拒否します。GitHub Actionsはキャッシュの更新状態を確認するだけで、外部APIを必須にしません。ブラウザの個人メモや広告企画、調査CSVを外部LLMへ送信しません。詳細は [AI_EXPLANATIONS.md](AI_EXPLANATIONS.md)。
