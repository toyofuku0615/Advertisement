# 未対応事項と改善ロードマップ

この版は操作できる静的リサーチアプリです。ただし、最新の世界的流行・生活者属性別人気の網羅的な観測が完成したとはしていません。収集器の実行結果、固定版履歴、利用者の取り込みを区別して利用してください。

## 現在の制約

| 項目 | 現在できる範囲・残る課題 |
| --- | --- |
| 現行 API の接続 | 2026-10-21 の実収集で Google RSS 4か国40観測と Bluesky `bsky.app` 公開フィード12件に成功。Bluesky キーワード検索は403、GDELT は503、YouTube はキー未設定。各操作の成功範囲を分け、パーサーテスト成功だけで接続成功とはしない |
| 同梱実履歴 | Google 公式の環境関連3トピック、16か国、2012–2023年の年次履歴。18か国を要求したが、米国・ベトナムは原資料になく補完していない。現在の文化トレンドの代わりではない。正規化範囲不明なので国間順位は不可 |
| 自由な検索語 | 画面は取得済み JSON の検索。任意語の過去/現在データをブラウザから自動生成しない。収集 CLI の `--keywords` または公式 CSV を使用 |
| SNS 観測 | Bluesky の限られた検索標本と、任意設定の YouTube mostPopular。全ネットワーク・全ジャンル・属性別の人気を代表しない |
| ニュース地図 | GDELT の最大50記事の返却標本の報道機関所在国。記事で言及された場所、読者居住地、文化の発生地を示さない。全面的な報道量統計ではない |
| 検索関心 | 急上昇 RSS と任意語の地域/時系列 CSV を別扱い。無料の一般公開 API から全世界の日次任意語データを取得できるとはしない |
| 時系列の粒度 | 観測された日時だけを表示。年次履歴を日次に補間しない。欠損を0に変えない |
| 都道府県 | CSVを地域名/コードで取り込み、一覧と推移に表示可能。都道府県境界ヒートマップは未対応 |
| 多言語トピック | 別名の編集は利用者確認が前提。原典観測IDを含む複数トピックの完全な統合・分離は未実装。意味的な自動翻訳統合、重複と同音異義語の完全解決はしない |
| 複数系列CSV | 時系列CSVは日付と1系列の2列に制限。複数国を含む列名から地域・正規化を推測せず、系列ごとに国と条件を指定して取り込む |
| 生活者調査 | 公開資料へのリンクと許諾のある利用者CSV。生活定点は公式規約が私的利用のみ、商用は事前承諾、改変/AI入力/スクレイピング禁止のため参照リンク限定・同サイトCSV取込不可。属性実測資料は初期同梱していない |
| 属性の代理指標 | 属性確認済みコミュニティの体系的なカタログはない。投稿者の年代・性別・学生/社会人属性を推定しない |
| 分析指標 | Momentum/Persistenceは同一定義と十分な履歴がある系列のみ。Noveltyは必要な180日履歴等がないため未算出。関連性・広告機会は定性仮説で、検証済みの確率や総合点はない |
| クリエイティブ | 手動の原典URL保存・表現分類。自動広告収集・動画ダウンロード・埋め込み再生の網羅対応はない。成果不明のCVR/ROASを補完しない |
| LLM | 保存済みの日本語AI文脈解説と任意のローカルOllama生成に対応。自動収集だけでは新規文章を生成しない。初期42話題以外は生成未接続なら未生成/更新待ち。ブラウザからの外部LLM接続・チャットは未実装 |
| ブランドセーフティ | キーワードによる簡易検出。文脈・皮肉・多言語・当事者への影響を完全には検査できない。広告利用前に人が判断する |
| 保存・共有 | ブラウザ IndexedDB のみ。ログイン、端末同期、共同編集、Notion保存、クラウドバックアップは未実装 |
| 言語 | 日本語中心。英語資料・多言語トピックを扱えるが、全画面の英語UI切替は未実装 |
| データモデル | Evidence / ContentItem は repository adapter で独立した読み取りモデルへ投影。永続 JSON は Observation の原典情報を正とし、別テーブルの保存や独立 CRUD は未実装 |
| データ削除追従 | Google/GDELT/YouTubeの30日保持、Blueskyの24時間キャッシュと標本更新はあるが、原投稿の削除/非公開化の自動検知、公開サービスの通報・削除受付システムは未実装。一般公開時は運用者の連絡先と対応フローが必要 |
| 定期実行 | GitHub Actions は設定ファイルを用意。実リポジトリでの有効化、書込権限、スケジュールの実運転は別途必要。時刻や成功を保証しない |
| 公開 | GitHub Pagesへ2026-10-21に公開済み。main更新・収集成功後・手動実行に対応。Blueskyは公開用JSONから除外し、連絡先・削除窓口の整備後に有効化 |

## 改善の順序

1. **最新データの検証:** 許可された収集ネットワークで公式 RSS / Bluesky / GDELT の実収集を再実行。応答・日時・国の意味・利用条件を最新文書で確認し、取得成功・ゼロ件・エラーを継続監視する。YouTube は必要なら利用者のキーで任意検証
2. **連続観測の品質:** 各 source / query / metric の観測範囲を固定し、重複・カバレッジ・欠損率を時系列で監査。GDELT の同じ記事の再取得による時系列重複を改善。取得頻度変更を別系列として管理
3. **地理・比較:** 無料利用条件を確認した都道府県境界、CSV複数系列の安全な取り込み、正規化範囲を確認できる比較データ、先行遅行の頑健性評価を追加
4. **調査の深さ:** 許諾された公開調査の source adapter と設問カタログ、調査母集団・調査方法の比較設計を整備。生活定点は現行の禁止条件を尊重して参照のみとし、無断の収集・AI要約を追加しない。代表性を確認したコミュニティ代理指標を明示的に登録
5. **継続利用:** 保存研究の差分監視、同期と共同編集を任意機能で追加。Notion の年→月→日への書き出しをMVPの次段階で実装
6. **補助分析:** 任意ローカルOllama adapterを実装済み。継続生成を運用する場合のモデル導入・品質監査を整備。数値は観測値だけを参照させ、主張と根拠IDの対応・反証・レビューを必須にする
7. **公開サービス運用:** 連絡先、権利者の削除リクエストと違反報告、原典削除への追従、依存ライセンス通知、障害監視を整備。商用化時は用途を許すホスティング・契約を別途選ぶ

優先順位は、見た目やAI生成量を増やすことより、取得できた根拠の正確さ、観測範囲、欠損、比較可能性を確認できることに置きます。
