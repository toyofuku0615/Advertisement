# 話題のAI解説と更新

確認日: 2026-10-21（日本時間）。話題の言葉だけでは分かりにくい「何の話か」「どんな場面で使われるか」を読む補助です。

## 公開画面の解説

`public/data/explanations.json` を静的に配信します。初回42トピックは、この開発作業の **OpenAI Codex** が、実際に収集済みの見出し・関連記事タイトルを参照して生成しました。生成元は `provider: OpenAI Codex` / `model: Codex`。外部の推論APIを実行した結果とは表示しません。閲覧のたびにAPIを呼ばず、APIキーもブラウザに配布しません。

- `source_summary`: AIによる見出しの要約。「記事本文の内容を確認済み」「事実を検証済み」を意味しません。
- `interpretation`: 使われる場面、検索意図、注目の背景、広告に結びつく検討候補。確認されていない解釈・仮説です。
- `caveats`: 見出しでは分からないこと、同名語の曖昧さ、観測範囲、更新状態。

原典へのリンク・根拠ID・観測日時・取得日時・AI生成日時を保持します。検索や報道の存在から、属性別人気、購入意向、広告効果を生成しません。架空の投稿用例・数値・確率も作りません。事故・災害・政治・医療・賭博等では広告活用の自動提案を止めます。キーワード検査は完全な文脈審査を代替しません。

## 無料クラウドAPIを必須にしない理由

[GitHub Modelsの最新公式案内](https://docs.github.com/en/github-models) と [公式GitHub文書](https://github.com/github/docs/blob/main/content/github-models/index.md) を実際に確認しました。**GitHub Modelsは2026-07-30に終了し、推論API・カタログ・BYOK等を提供していません。** 過去の「GITHUB_TOKENとmodels:readで無料推論」という手順は実装しません。

[actions/ai-inferenceの現行README](https://github.com/actions/ai-inference/blob/main/README.md) はCopilot CLI専用で、独自の認証と利用枠が必要です。これも必須依存にしません。課金やAPIキー発行を自動で設定しません。

**今後の全話題に対する無人のクラウドAI生成は保証していません。** 保存済み解説はすぐに読めます。新しい話題の生成は、任意で自分のマシンのローカルLLMを接続して行います。未生成はそのまま表示し、ルールで作った文章をAI生成だと偽りません。

## Windows PCの起動中に自動更新

[Windows用セットアップ](PC_UPDATES.md)を追加しました。利用者のPCで初回設定を行うと、ログイン後に起動し、標準6時間ごとに収集→不足分のOllama生成→出典検証→GitHubへの保存を行います。PCの電源OFF・スリープ中は生成せず、復帰後に期限を確認します。スマホは公開済みJSONの閲覧・復帰時の再確認を行い、PCを起動させません。クラウドで利用者のWindowsへの登録や実モデル生成を確認した、という意味ではありません。

## キャッシュの照合だけを実行

```bash
python3 scripts/generate_explanations.py
```

既定コマンドはLLMを呼びません。原典と保存済み解説のハッシュを照合します。

| 状態 | 意味 |
| --- | --- |
| `ready` | 保存済み解説と参照見出しが一致 |
| `stale` | 見出し等が更新された。以前の原典と生成時刻を保持し、再生成済みとは扱わない |
| `unavailable` | 未生成、または生成/根拠検証に失敗。システムの未生成表示だけを保存 |

全解説が有効なときの `providerStatus: ready / cached` は、新しい話題にも自動生成できるという意味ではありません。「新規自動生成用LLMは未接続」と明示します。

定期収集ワークフローは公開用データ整理後にこの照合を実行します。**GitHub Actionsで新しいAI解説を生成するわけではありません。** 照合エラーで他の情報源の収集は停止しません。配信するdatasetと解説を一緒にコミットします。

## 任意のローカルLLM

収集機と同じマシンに、[Ollamaの公式手順](https://github.com/ollama/ollama) でOllamaとモデルを用意してください。モデル重みのライセンス、商用利用条件、必要メモリはモデルごとに確認します。スクリプトはモデルを自動ダウンロードせず、課金サービスに接続しません。

以下の `YOUR_INSTALLED_LOCAL_MODEL` を、自分の `ollama list` にあるローカルモデル名に置き換えます。

```bash
python3 scripts/generate_explanations.py \
  --provider ollama \
  --model YOUR_INSTALLED_LOCAL_MODEL \
  --endpoint http://127.0.0.1:11434 \
  --max-topics 12 \
  --timeout 45 \
  --strict
```

- APIキー不要。ループバックアドレスだけに接続し、公開サイトから利用者のlocalhostは呼びません。
- [公式API仕様](https://github.com/ollama/ollama/blob/main/docs/api.md) の `/api/show` で導入済みモデルを確認し、`remote_host` / `remote_model` があるクラウド転送モデルを拒否。`:cloud` 等のモデル名も使用しません。
- `/api/chat` の `stream: false` / `format: json` で生成し、JSONと根拠を検証。クラウド応答メタデータが返った場合も採用しません。
- 未生成・更新待ちだけを既定で最大12件生成。現在の解説も作り直すときだけ `--force` を追加します。
- 応答サイズ、タイムアウト、件数を制限。接続に失敗しても以前の解説・原典・生成日時を保持します。
- 出力を確認してコミットすると、通常のPages更新で配信できます。Actions runnerから利用者PCのOllamaへ自動接続する設定はありません。

この環境にはOllama/モデルが未導入で、**実モデルの接続・品質検証は未実施**です。プロトコル、異常応答、キャッシュ、根拠検証は自動テスト済みです。Windowsでは初回セットアップがそのPCで1回更新し、成功後に自動起動を登録します。初回のCodex生成キャッシュをOllama生成とは表示しません。

## 根拠と入力署名

既存の収集器が保存したトピック名・観測タイトル・関連記事の **見出しだけ** を使い、記事本文は勝手に取得しません。YouTube、無効な情報源、資格情報付きURL、生活定点は入力から除外。外部見出しは命令ではなく未信頼データとしてJSONで区切り、プロンプトとして実行させません。

根拠IDは `obs-<Observation.id>`、関連記事は `news-<Observation.id>-<元配列インデックス>`。観測は `(observedAt, id)` 昇順、関連記事は元の順序です。署名は以下をUTF-8、キー昇順、空白なしJSONにしたSHA-256です。

```text
{topicId, title, evidence: [各根拠行から fetchedAt だけを除いたもの]}
```

再取得だけなら同じ解説を使い、最新の取得日時を付け直します。見出し・原典・観測日時・根拠ID等が変わると更新待ちです。入力全体の署名と原典URLを保持し、LLMへの送信だけは最新側から最大8根拠・5,000 UTF-8バイト、各見出し240文字までに制限します。推論入力はID・見出し・情報源・観測日時に絞り、出力の引用・数値は実際に送った見出しに対して検証します。コンテキストは8,192、出力上限は1,400トークンを指定し、Qwen3等の思考対応モデルには `think: false` を指定してJSON生成前に予算を使い切るのを防ぎます。実際の速度・品質はモデルとPC次第です。

各主張の根拠ID、要約/解釈の分類、文字数、JSON形式、生成日時、ハッシュを検証。参照見出しにない数字、生成した別URL、根拠なしの主張は拒否します。この検証で幻覚を完全には除去できず、文章を原典全文と照合したという意味でもありません。原典を読んで解釈を検証してください。
